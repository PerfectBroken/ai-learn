## 说明

这份文档记录`TokenEconomics.md`第2节"Token价格"表格里**"Claude Code平均请求期望花费"**这一列的计算方法和详细过程，表格里只放结果，完整计算放这里备查。

## 1 输入假设

用Claude Code的真实平均请求数据作为统一workload，套到每个模型上做对比：

| 参数 | 数值 | 来源 |
|---|---|---|
| 平均input token/请求 | 77,800 | 第三方实测：追踪1,289次真实请求、共100.9M token，[方法论公开](https://docs.bswen.com/blog/2026-03-10-claude-code-token-usage-per-request/) |
| 平均output token/请求 | 480 | 同上 |
| input缓存命中率 | 84% | 同上，100.3M input token中84.2M命中缓存 |
| input缓存未命中率 | 16% | 同上 |

## 2 计算公式

```
Input期望花费 = 77,800 × (0.84 × 缓存命中单价 + 0.16 × 未命中单价) / 1,000,000
Output花费    = 480 × output单价 / 1,000,000
单次请求期望总花费 = Input期望花费 + Output花费
```

output没有缓存机制，所以output花费不涉及命中率，直接按标准output单价计算。

## 3 逐模型计算过程

单价数据来自`TokenEconomics.md`第2节表格（均为每百万token美元价）。

### Claude Opus 5
- 单价：miss $5.00 / hit $0.50 / output $25.00
- 混合input单价 = 0.84×0.50 + 0.16×5.00 = 0.42 + 0.80 = **1.22 $/M**
- Input花费 = 77,800 × 1.22 / 1e6 = **$0.094916**
- Output花费 = 480 × 25 / 1e6 = **$0.012000**
- **总计 = $0.106916 ≈ $0.1069**

## 4 结果汇总（按花费从低到高排序）

| 模型 | Input期望花费 | Output花费 | 单次请求期望总花费 |
|---|---|---|---|
| DeepSeek-V4-Flash | $0.0019 | $0.0001 | $0.0021 |
| GPT-5.6 Luna | $0.0038 | $0.0006 | $0.0044 |
| DeepSeek-V4-Pro | $0.0057 | $0.0004 | $0.0061 |
| Claude Sonnet 5 | $0.0380 | $0.0048 | $0.0428 |
| Kimi K3 | $0.0569 | $0.0072 | $0.0641 |
| Claude Opus 5 | $0.0949 | $0.0120 | $0.1069 |
| GPT-5.6 Sol | $0.0949 | $0.0144 | $0.1093 |

最便宜（DeepSeek-V4-Flash）和最贵（GPT-5.6 Sol）差了约52倍。Input在总花费里占绝对大头（Claude Opus 5的$0.1069里，input贡献了$0.0949，约89%），哪怕84%都命中了缓存——input的绝对量级（77,800 token）远超output（480 token），压过了缓存折扣带来的节省。

## 5 方法论局限

**84%的input缓存命中率，是Claude Code在Claude自家缓存系统上实测出来的**，这里把它当作统一假设套用到了所有模型（GPT-5.6、DeepSeek、Kimi）身上做对比，**不代表这几家模型在真实使用中也会跑出84%的命中率**。不同厂商的缓存机制不同：

- 缓存时效不同（Claude默认5分钟/1小时两档，DeepSeek、Kimi的缓存有效期未必一致）
- 命中判定粒度不同（按完整prefix匹配还是更细粒度匹配）
- 实际agent工具（Claude Code、Cursor、Codex）针对不同后端模型的上下文管理策略也可能不同，进而影响真实命中率

所以这份计算的意义是"用同一个真实workload去横向比较各家定价结构"，不是"在其他模型上实测出来的真实平均花费"。要拿到其他模型的真实平均花费，需要针对该模型单独做类似Claude Code那样的用量追踪。
